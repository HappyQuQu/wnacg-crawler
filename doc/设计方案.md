# Python 版 WNACG 漫画爬虫重设计方案

> 将 C# 版本重写为**带 Web 前端的 Python 应用**，通过 Docker 单容器部署，提供可视化操作界面与实时进度反馈，同时修复原版所有已知问题。

---

## 整体架构

```
┌─────────────────────────── Docker 容器 ─────────────────────────┐
│  浏览器 ➡ http://localhost:8080                                  │
│                                                                   │
│  ┌─────────────────────┐   ┌─────────────────────┐              │
│  │  左屏：代理浏览器   │   │  右屏：下载面板      │              │
│  │  wnacg 页面内嵌     │   │  任务列表与进度      │              │
│  │  「加入下载」按钮   │   │  实时 WebSocket      │              │
│  │  注入到页面中       │   │  设置面板            │              │
│  └─────────────────────┘   └─────────────────────┘              │
│           │                          │                            │
│  ┌────────────────────────────────────────────────┐              │
│  │             FastAPI 后端                        │              │
│  │  /proxy  - 反向代理 wnacg + 注入按钮           │              │
│  │  /api    - 任务增删查 REST                      │              │
│  │  /ws     - WebSocket 进度推送                   │              │
│  │  爬虫引擎 - asyncio 异步下载                    │              │
│  └────────────────────────────────────────────────┘              │
└───────────────────────────────────────────────────────────────────┘
```

**工作流程**：用户在左屏浏览 wnacg → 看到喜欢的本子点「加入下载」→ 右屏实时显示进度。

## 技术选型

| 功能 | C# 旧版 | Python 新版 |
|---|---|---|
| **Web 框架** | 无 | `FastAPI`（异步，自带 WebSocket） |
| **代理浏览器** | 无 | `/proxy` 路由（BeautifulSoup4 改写链接） |
| **前端** | 无 | Vanilla JS 左右分屏布局 |
| **实时进度** | 无 | `WebSocket`（asyncio 原生支持） |
| HTTP 请求 | `HttpClient`（每次新建）| `httpx.AsyncClient`（单例，连接池） |
| HTML 解析 | 手写正则 | `BeautifulSoup4` |
| 数据库 | 手写 SQL 拼接 | `SQLAlchemy 2.0` async ORM |
| 配置管理 | JSON + Newtonsoft | `pydantic-settings` |
| 并发控制 | `SemaphoreSlim` | `asyncio.Semaphore` |
| **日志** | 手写文件（有 mm/MM bug）| `loguru`（`enqueue=True`）|
| 打包 ZIP | `System.IO.Compression` | `zipfile`（标准库） |
| 重试策略 | 手写递归（有问题）| `tenacity` 声明式重试 |
| **部署** | 无 | Docker 单容器 |

### `config.py` — 配置管理

启动时加载一次并缓存（修复 C# 版每次访问重读磁盘的问题）。

```python
class AppConfig(BaseSettings):
    is_zip: bool = True
    max_thread: int = 10        # 并发下载上限
    re_count: int = 5           # 重试次数
    download_path: str = "/data"          # 挂载点：下载文件
    db_path: str = "/config/data.sqlite"  # 挂载点：SQLite 数据库
    manga_main_url: str = "https://www.wnacg.com/"

    proxy: ProxyConfig = ProxyConfig()
    model_config = SettingsConfigDict(json_file="/config/config.json")
```

### `crawler/downloader.py` — HTTP 下载器

- **单例** `httpx.AsyncClient`（修复 C# 版连接池耗尽问题）
- `asyncio.Semaphore` 控制并发数
- `tenacity` 指数退避重试（修复 C# 版递归重试）

```python
class Downloader:
    _client: httpx.AsyncClient  # 应用级单例，统一管理

    @retry(stop=stop_after_attempt(5), wait=wait_exponential(min=1, max=10))
    async def get_text(self, url: str) -> str: ...
    async def get_bytes(self, url: str) -> bytes: ...
```

### `service/manga_service.py` — 业务逻辑 + 进度发布

每个步骤完成时，向 WebSocket 广播进度事件：

```python
class MangaService:
    async def run(self, manga_id: str, broadcast: Callable):
        await broadcast({"stage": "info", "manga_id": manga_id, "status": "fetching"})
        await self._fetch_info(manga_id)
        await broadcast({"stage": "download", "progress": 0, "total": pic_count})
        await self._download_images(manga_id, broadcast)
        if config.is_zip:
            await self._zip_manga(manga_id)
        await broadcast({"stage": "done", "manga_id": manga_id})
```

### `api/proxy_router.py` — 反向代理浏览器 ✨ 新增

后端充当 wnacg 的透明代理，让用户在前端直接浏览：

```python
@router.get("/proxy")
async def proxy(url: str):
    # 1. 用 httpx 获取 wnacg 原始 HTML
    html = await downloader.get_text(url)
    soup = BeautifulSoup(html, "html.parser")

    # 2. 重写所有链接，使页内跳转也走代理
    for tag in soup.find_all(href=True):
        tag["href"] = f"/proxy?url={quote(urljoin(base, tag['href']))}"

    # 3. 漫画详情页：注入「加入下载」按钮
    if is_manga_detail_page(url):
        manga_id = extract_manga_id(url)
        inject_download_button(soup, manga_id)

    return HTMLResponse(str(soup))
```

**要点：**
- 图片 `src` 同样走代理路由，无跨域问题
- 代理请求复用同一个 `httpx.AsyncClient`（含代理配置）
- 仅允许代理 wnacg 域名，防止被用作开放代理

### 日志方案（修复 asyncio 并发写入问题）

`loguru` 默认 sink 在 asyncio 并发环境下会出现日志乱序或丢失，使用 `enqueue=True` 解决：

```python
logger.add(
    "logs/{time:YYYY-MM-DD}.log",   # 修复原版 mm→MM 的 bug
    rotation="00:00",               # 每天滚动
    enqueue=True,                   # ✅ 解决 asyncio 并发写入问题
    encoding="utf-8",
)
```

### `frontend/` — Web 界面（左右分屏）

Vanilla JS + CSS，由 FastAPI `StaticFiles` 托管。

**左屏 — 代理浏览器**
- 渲染由 `/proxy` 返回的 wnacg 页面（所有链接已重写为代理内跳转）
- 漫画详情页注入悬浮「**+ 加入下载**」按钮
- 点击按钮 → 调用 REST API → 任务加入右屏队列

**右屏 — 下载面板**
- 📊 任务状态卡片（排队 / 下载中 / 完成 / 失败）
- 🔄 实时进度条：WebSocket 驱动，图片数 / 总数
- ⚙️ 设置面板：并发数、代理、ZIP 开关
- 🌙 暗色主题

## Docker 部署

### Dockerfile

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY backend/ ./backend/
COPY frontend/ ./frontend/
RUN pip install -r backend/requirements.txt
VOLUME ["/data", "/config"]   # /data=下载文件  /config=配置+数据库
EXPOSE 8080
CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8080"]
```

### docker-compose.yml

```yaml
services:
  wnacg:
    build: .
    ports:
      - "8080:8080"
    volumes:
      - ./data:/data        # 📁 下载文件持久化（漫画图片/ZIP）
      - ./config:/config    # ⚙️  配置 + SQLite 数据库持久化
    restart: unless-stopped
```

### Volume 说明

| 宿主机路径 | 容器挂载点 | 内容 |
|---|---|---|
| `./data/` | `/data` | 下载的漫画图片、ZIP 包 |
| `./config/` | `/config` | `config.json`（配置）、`data.sqlite`（数据库）|

**启动命令：**
```bash
docker compose up -d
# 访问 http://localhost:8080
```

## 修复 C# 版已知问题清单

| # | 原版问题 | Python 版解决方案 |
|---|---|---|
| 1 | **SQL 注入** | SQLAlchemy ORM，无手写 SQL |
| 2 | **每次 new HttpClient** | `httpx.AsyncClient` 单例 |
| 3 | **递归重试** | `tenacity` 声明式重试 |
| 4 | **`.Result` 阻塞 async** | 全程 `async/await` |
| 5 | **IsFinished/IsError 用字符串** | SQLAlchemy `Boolean` 字段 |
| 6 | **Config 每次读磁盘** | `pydantic-settings` 启动时加载一次 |
| 7 | **SaveFile.append 逻辑矛盾** | 直接用 `open(mode='a')`，行为正确 |
| 8 | **日志时间格式 `mm` bug** | `loguru` + `enqueue=True` |
| 9 | **大量废弃注释代码** | 新版不迁移废弃代码 |
| 10 | **PicIndex 重复赋值** | ORM 不存在此问题 |
